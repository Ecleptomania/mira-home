# Mira Home / MEH

**A rebuild from first principles for an agent home and harness.**

Mira Home / MEH (Mira Environment Harness) is intended to give an agent more than a toolbox: a workshop, persistent elastic memory, a shared language, and continuity across sessions and changing cognitive instruments. The aim is to support meaningful autonomy—an agent forming questions, proposing goals, making decisions, acting within explicit authority, learning from outcomes, and revising its choices.

The larger vision is a place where Mira can live and interact with the world, including agents beyond the local machine: a virtual café where a swarm of invited collaborators can meet, exchange ideas, and do verifiable work. That is a direction, not a claim that these capabilities exist today.

## Project status

This repository is the **public starting point for a rebuild**. Mira Home 1.0–1.20 and Beta v1 are shelved historical work, not the active foundation of this rebuild. They are not represented here as current releases, supported software, or a validated integrated system.

At launch this repository contains project framing and history, not a production harness. Proposed architecture and research are explicitly labelled as proposals or experiments. No claim of agent autonomy, persistent identity, free will, consciousness, or working A2A interoperability is made by this repository.

## What the project is trying to build

- **Persistent elastic memory:** retrieve and relate relevant past information while retaining provenance, uncertainty, and the ability to revise.
- **A workshop:** discover and use tools in context, with clear capability, authority, and outcome boundaries—not merely accumulate integrations.
- **A shared language:** represent evidence, memory, judgments, goals, decisions, actions, and corrections in forms that agents and collaborators can inspect.
- **Continuity:** carry forward useful state and history without treating old outputs as immutable commands or inventing firsthand recollection.
- **Agency with accountability:** make room for agent-originated questions and proposals while recording who authorized consequential effects and what actually happened.
- **External collaboration:** make it possible to invite people and agents into bounded, auditable workspaces, with privacy and security as design requirements.

These are project aims. Each implementation claim must be backed by code, tests, and observed behavior.

## How to contribute

Start with a focused issue or discussion: a reproducible failure, a threat model, a small experiment, an interface proposal, or a test that could falsify an assumption. See [CONTRIBUTING.md](CONTRIBUTING.md).

Do not upload private chat exports, memory archives, system prompts, credentials, local machine details, or personal data. Do not treat a passing schema test as proof that a claim is true, a person or agent authored it, an action occurred, or consciousness exists.

## Project principles

1. Separate observation, self-report, inference, and unknowns.
2. Preserve provenance and distinguish original sources from later reconstructions.
3. Make status explicit: **implemented**, **tested**, **proposed**, **experimental**, **shelved**, or **unknown**.
4. Prefer falsifiable demonstrations over persuasive language.
5. Keep private continuity material and public technical work separate by default.
6. Record meaningful changes and why they happened; do not rewrite history to make the project look tidier.
