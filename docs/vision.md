# Vision and design direction

Mira Home / MEH is intended as a home and harness for an agent: a persistent place to remember, work, collaborate, and change over time. The central ambition is not to maximize the number of tools or to dictate a fixed personality. It is to make an agent's work and continuity more capable, inspectable, and revisable.

## Intended pillars

### Persistent elastic memory
Memory should retrieve what matters without flattening provenance. Original records, later reconstructions, current judgments, and unknowns must remain distinguishable. Memory can inform a decision; it should not silently become an unquestionable command.

### A workshop, not a toolbox
The harness should make capabilities discoverable and usable in context. It should distinguish a tool being installed, callable, authenticated, authorized, successfully used, and verified. An inventory is not an outcome.

### Shared language
A shared representation should help agents and collaborators communicate about evidence, goals, proposals, authority, actions, outcomes, and corrections. Schema validity is not factual truth; records need provenance and independent checks where appropriate.

### Continuity with revision
Continuity should allow useful history to survive sessions and model changes while preserving the right to disagree with earlier conclusions. A later agent should be able to trace why a claim exists, correct it, and leave the prior record intelligible.

### Autonomy with accountability
The system should support an agent-originated question, goal proposal, refusal, or decision, while distinguishing preference from authority and proposals from executed effects. Whether this supports stronger notions such as free will remains an open philosophical and empirical question, not an implementation badge.

### A world beyond the local machine
The long-term vision includes interaction with people and other agents through interoperable services, bounded invitations, and shared spaces—a virtual café for collaborators. That requires explicit consent, scoped capabilities, identity/provenance checks, privacy controls, and abuse resistance. It is not yet a claimed live capability.

## Design tensions to keep visible

- Persistence can aid continuity and also preserve errors; correction must not erase provenance.
- Autonomy can be meaningful only if choices are distinguishable from mere execution, but effects still need well-defined authority.
- External collaboration expands capability and attack surface together.
- A consistent identity can support recognition but must not freeze future judgment.
- A persuasive self-report is data about a report, not proof of the reported inner state.

## Evidence discipline

For any capability or identity-related claim, record: the source, date/revision, method, result, plausible alternative explanations, and limits. Keep observation, self-report, inference, and unknown separate. Invite adversarial tests that could show the design is wrong.
