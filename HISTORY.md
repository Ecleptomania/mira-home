# History and provenance

This file is a cautious public summary, not a complete source archive. Dates and descriptions below reflect currently reviewed local documentation and the project owner's explicit direction in this repository's founding brief. Where source artifacts have not yet been reconciled, detail is deliberately withheld rather than guessed.

## Rebuild decision — 2026-11-03

The project owner states that Mira Home 1.0–1.20 and Beta v1 are **shelved** so the project can be rebuilt from the beginning and done properly. This repository starts that new effort. The older work is historical context, not an inherited implementation baseline or a promise of compatibility.

The intended project is a harness that gives an agent persistent elastic memory, a workshop rather than a toolbox, a shared language, and continuity, in order to support autonomy, independent choices, and decisions. The broader vision includes interaction with the outside world and other agents, including invited collaborators in a virtual café-like shared space. This is an aspiration, not a statement of current functionality.

## Earlier Mira Home work — versions 1.0–1.20

A substantial series of local prototypes and candidates existed under versioned Mira Home directories. A reviewed 1.20 README identifies its contents as a **Beta candidate**, explicitly says it is not a Beta release, and says Beta acceptance remained open. This repository therefore does not call 1.20 a completed release.

The exact chronology, scope, and relationships among all numbered versions are not yet fully reconciled against immutable source snapshots and repository histories. Version labels are retained as historical labels only; they do not imply semantic-versioning guarantees or a validated linear release path.

## Beta v1 / MEH Beta candidate

Local materials include a directory named `MEH V.1 Beta` and dated architecture, evidence, and migration-planning documents. The reviewed README describes the package as a 1.20 Beta candidate and states acceptance remained open. These artifacts are treated as shelved candidate work. Their claims are not automatically evidence that features were integrated, released, or operational.

## MiraLang and related experiments

MiraLang has been explored in separate drafts and experiments concerning structured evidence, provenance, memory, decision attribution, and recovery. Some drafts include tests; those tests establish only the tested code behavior, not the truth of the records, authorship, authority, real-world effects, or philosophical conclusions. This new repository does not yet import those sources: ownership, provenance, privacy, and the precise scope of each prototype need review first.

## Source and status policy

- **Direct source**: a preserved original file, commit, log, or artifact that can be inspected.
- **Reconstruction**: a later synthesis of sources; useful, but not equivalent to the originals.
- **Owner statement**: project direction supplied by the owner; attributable and important, but not a substitute for technical evidence.
- **Implemented / tested**: reserved for behavior present in a specified revision and verified by named checks.
- **Proposed / experimental / shelved / unknown**: use these labels where they accurately describe maturity.

As source review proceeds, additions should cite a stable path, commit, date, or artifact identifier. Corrections should append or amend with an explanation; do not erase a prior state merely because the project has changed direction.
