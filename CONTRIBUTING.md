# Contributing

Thanks for helping build Mira Home / MEH from a clean foundation. Useful contributions include focused design critiques, threat models, reproducible experiments, tests, documentation, and small implementation proposals.

## Before opening a contribution

- Check whether the idea is already tracked; explain the problem and the evidence.
- State what is **observed**, what is **inferred**, what is **proposed**, and what remains unknown.
- Keep examples synthetic or public. Never attach private chats, memory stores, identity/profile files, logs, credentials, personal data, or machine-specific configuration.
- Avoid presenting a prototype, passing test, or agent self-report as proof of broad capability or consciousness.

## Good first contributions

- A minimal test that exposes a specific failure mode in provenance or continuity.
- A threat model for safe delegation to external agents.
- A review of the boundaries between memory, identity, authority, and execution.
- A small, testable interface proposal with explicit non-goals and failure cases.

## Review expectations

Changes should be inspectable, narrowly scoped, and include tests where behavior changes. Public contributions may be revised or declined; no external contributor is granted access to private systems or archives by contributing here.
